A Realidade das APIs

Documentação de API sempre foi tarefa de "depois".

Adiada sprint após sprint, negligenciada em code reviews e, no fim do dia, quase sempre mentirosa. Documentação desatualizada é muito pior que nenhuma: gera falsa sensação de segurança e quebra integrações em produção.

warning YAMLs manuais envelhecem e mentem. O código não mente.
sync_disabled

YAMLs e JSONs manuais desatualizados

Manter um arquivo Swagger de 2.000 linhas separado do código é um convite a erros. Alguém renomeia um campo na struct e esquece de atualizar a documentação.

code_blocks

O código como a Única Fonte da Verdade

O CliDoc inverte essa lógica. A rota é documentada logo acima da função handler onde você já passa o dia trabalhando. O arquivo OpenAPI é apenas um artefato derivado da compilação.

bolt

Zero Reflection • Zero Execução em Runtime

O CliDoc nunca inicializa o seu servidor nem executa código de aplicação. Ele analisa estritamente a árvore sintática (AST) e blocos de comentários, garantindo segurança e execução instantânea.

Arquitetura de Engine

Pipeline Linear em 5 Camadas

Da AST do código até o arquivo final OpenAPI em milissegundos.

1

CLI Core

Carrega flags, valida paths e interpreta configurações opcionais em clidoc.yaml.

Engine Flag Loader
2

AST Parsers

Lê tokens e comentários via parser sintático oficial de Go, extraindo anotações sem invocar o runtime.

Static AST Walk
3

IR Neutra

Representação intermediária que abstrai rotas, payloads e status, desacoplando linguagens de geradores.

Coração Plugável
4

Generators

Compila a IR em especificações estritas OpenAPI 3.0 (JSON) ou arquivos formatados em Markdown.

JSON / MD Exporter
5

Server & UI

Servidor HTTP interno que monta o Swagger UI / Redoc interativo com hot-reload a cada alteração de arquivo.

Sintaxe Padrão

Familiar para devs, legível para máquinas

Se você já viu anotações Swagger/Go-Swagger, está em casa. A sintaxe é simples, intuitiva e não polui seus arquivos.

handlers/user.go
Anotações CliDoc
// CreateUser lida com o registro de novas contas
// @Summary Criar Novo Usuário
// @Description Cadastra um novo usuário no sistema
// @Route POST /api/v1/users
// @Tag Usuários
// @Param body json UserRequest true "Dados do usuário"
// @Success 201 json UserResponse "Usuário criado com sucesso"
// @Failure 400 json ErrorResponse "Dados inválidos"
func CreateUser(w http.ResponseWriter, r *http.Request) {
  // Sua lógica de negócio real aqui...
  var req UserRequest
  json.NewDecoder(r.Body).Decode(&req)
  // Retorna status 201 Created
  w.WriteHeader(http.StatusCreated)
}

Arsenal de Produtividade

Comandos diretos, DX implacável

MVP Disponível build
clidoc generate

Varre o diretório do seu projeto via AST, compila a IR e gera o arquivo dist/openapi.json em tempo recorde sem travar seu terminal.

Flags: --out, --format json|yaml
Fase 2 • Em Breve tune
clidoc init

Cria interativamente um arquivo de configuração clidoc.yaml contendo metadados gerais da API, servidores, licença e filtros de exclusão.

Config: Info, Servers, Tags, IgnoredDirs
Fase 2 • Em Breve public
clidoc serve

Inicia um servidor local embutido fornecendo uma interface Swagger UI ou Redoc com Hot Reload automático sempre que um arquivo for salvo.

Porta default: 8080 (Configurável)
